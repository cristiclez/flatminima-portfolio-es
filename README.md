# flatminima-portfolio-es

**Portfolio Risk Engine & Sharpness-Aware Allocator** (work in progress)

A risk engine (GARCH / filtered historical simulation, VaR and Expected Shortfall with
regulatory-style backtesting) and a differentiable portfolio allocator trained with
Sharpness-Aware Minimization (SAM), benchmarked against Adam and convex baselines.

> **Status: v0.1 in progress.** Only the items marked "done" below exist. Nothing here
> claims regulatory (FRTB) compliance; "FRTB-style" means ES at 97.5% with backtesting.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
make install            # editable install with dev + data extras
make data-synthetic     # offline demo on SYNTHETIC data (labelled as such)
make data               # real data from Yahoo Finance (needs internet)
make risk               # rolling VaR/ES forecasts (after `make data`)
make backtest           # formal backtests -> docs/backtest_results.md
make robustness         # 500-day window variant (out-of-sample covers 2008)
make portfolio          # walk-forward baselines -> docs/portfolio_baselines.md
make riskfree       # 3-month T-bill (FRED DTB3) into the database (after `make data`)
make experiments    # spec B: Adam vs SAM + Hessian analysis -> docs/portfolio_specB.md (needs torch)
make test               # pytest
make lint               # ruff
```

On Windows (PowerShell): `.venv\Scripts\activate`, and run the `python -m ...` commands from the Makefile directly if `make` is unavailable.

## Data

- **Real:** daily adjusted closes of 28 liquid US-listed ETFs from 2005 via Yahoo Finance
  (`yfinance`). Data is for personal/research use under Yahoo's terms and is **never
  committed**; `make data` rebuilds it.
- **Synthetic:** GARCH(1,1)-t simulations with known parameters, used to validate
  estimators and tests and to run the pipeline offline. Any result computed on synthetic
  data is labelled as such.

## Known limitations

- Survivorship bias: the universe contains only ETFs that exist today.
- Yahoo adjusted prices can contain errors; the quality checks flag, but do not fix, them.
- One extreme observation is flagged and deliberately retained: EWZ, 2020-03-16
  (log return approx. -0.26), consistent with same-day falls in SPY and EEM (COVID-19 crash).

## Risk engine (week 2)

**Model.** GARCH(1,1) and GJR-GARCH(1,1) with unit-variance Student-t innovations, exact
maximum likelihood (SLSQP, covariance-stationarity constraint), standard errors from the
numerical observed Hessian, and Hessian condition number reported per fit.

**Forecasts.** Rolling window of 1,000 days, refit every 20 days (warm start), one-step-ahead
filtered historical simulation (Barone-Adesi et al., 1999): VaR at 99% and 97.5%, and ES at
97.5% (the FRTB-style level). Losses are positive numbers on a unit-notional position, with
log returns as the P&L proxy. Unfiltered historical simulation is kept as a baseline.

**What has been verified (all on simulated data with known truth).**

- Parameter recovery: the mean MLE over 10 replications matches the true GARCH and GJR
  parameters within stated tolerances (`tests/test_garch.py`).
- Cross-check against the `arch` package (`scripts/validate_against_arch.py`): alpha, beta and
  gamma agree to about 1e-4; nu to about 1e-2.
- Ljung-Box and ARCH-LM implementations match `statsmodels` to machine precision.
- No look-ahead: changing returns from day k onwards leaves all earlier forecasts unchanged.
- Properties (Hypothesis): ES >= VaR at the same level, VaR increasing in confidence,
  scale equivariance, vectorised variance filter equals the textbook loop.

## Backtesting (week 3)

**Tests.** Kupiec proportion-of-failures (Kupiec, 1995), Christoffersen independence and
conditional coverage (Christoffersen, 1998), Basel traffic light over rolling 250-day windows,
and Acerbi-Szekely Z1/Z2 for ES at 97.5% (Acerbi and Szekely, 2014). Z1/Z2 p-values come from
a Monte Carlo under H0 that draws each day's P&L from that day's own FHS predictive
distribution. A test "passes" when it does not reject at 5%; passing is weaker than proving
the model correct, and no multiple-testing correction is applied.

**How the tests themselves were validated (simulated data with known truth).**

- Kupiec and Christoffersen agree with independent implementations (binomial log-pmf and an
  explicit Markov-chain likelihood). Basel zones reproduce the published 250-day table.
- Size and power: Kupiec and Christoffersen reject at about their nominal rate under H0 and
  reject clearly wrong models. For Acerbi-Szekely, a 1,500-replication study under H0 gave
  rejection rates of 4.4% (Z1) and 5.7% (Z2) at the 5% level.
- End to end: a correctly specified FHS-GJR model is not rejected by any test, while the same
  forecasts scaled down by 35% are rejected by Kupiec, Christoffersen and Acerbi-Szekely.
- Unfiltered historical simulation passes Kupiec on clustered data but fails Christoffersen
  independence, which is the practical reason to run both tests.

**Real-data results.** Run `make backtest` after `make risk`; the report is written to
`docs/backtest_results.md`. The default 1,000-day window means the out-of-sample period starts in
2009, so the 2008 peak lies inside the estimation window; `make robustness` repeats the exercise
with a 500-day window so that 2008 is evaluated out of sample (at the cost of noisier estimates).

## Portfolio baselines (week 4)

**Estimators.** Sample covariance, Ledoit-Wolf (2004) shrinkage (matches `scikit-learn` to
machine precision) and Random-Matrix-Theory cleaning (eigenvalues inside the Marchenko-Pastur
bulk replaced by their mean). **Strategies** (long-only, fully invested): equal weight, minimum
variance with each estimator, and minimum CVaR at 97.5% (Rockafellar-Uryasev, cvxpy/Clarabel).

**Evaluation.** Walk-forward with a 252-day lookback and monthly (21-day) rebalancing; each
rebalance sees only past data (tested: altering later returns leaves earlier results unchanged).
Transaction costs are explicit (5 bps per unit of traded notional). Sharpe ratios carry Moving
Block Bootstrap intervals (block of order n^(1/3), all strategies resampled jointly, so
differences versus equal weight are paired).

**Honest note on the estimators.** In a controlled simulation (one common factor plus noise,
N=28-50 assets, T=60-252 days) neither Ledoit-Wolf nor RMT beat the sample covariance
consistently: they won in some configurations and lost in others. This repository therefore
makes no claim that they improve the portfolios; the real-data comparison is reported as
measured. The Moving Block Bootstrap behaves as expected: its interval is wider than an i.i.d.
bootstrap under autocorrelation, and coverage was 92.5% for a nominal 95% on i.i.d. data.

## Week 5: differentiable allocator, Adam vs SAM, Hessian analysis

**What exists.** A PyTorch allocator that minimises in-sample CVaR at 97.5% (Rockafellar-Uryasev form, checked against the cvxpy optimum), in two versions: free logits per asset ("direct") and a small network shared across assets that maps past features (21/63-day volatility, 21/126-day return, cross-sectionally standardised) to weights ("policy"). Weights come from a softmax with a per-asset cap. Both are trained with Adam and with SAM (Foret et al., 2021), with the same number of gradient evaluations. Curvature at the trained point is measured with Hessian-vector products (double backprop): Lanczos for the top eigenvalues, Hutchinson for the trace, and a one-step sharpness.

**What has been verified (tests).** SAM's update matches the closed-form formula; SAM with rho = 0 equals Adam; on a toy problem with a continuum of minima of different curvature SGD ends at lambda_max 9.2 and SAM(0.2) at 2.0; Lanczos, Hutchinson and the Hessian-vector product agree with dense linear algebra; the capped softmax sums to one and respects the cap; the features use only past data; the CVaR loss matches the cvxpy solution.

**Specification B is post hoc.** Specification A (above) degenerated: the minimum-variance portfolio held about 97% in a short Treasury ETF, and Sharpe ratios had no risk-free rate. Specification B (excess returns over the 3-month T-bill, 10% cap per asset, 756-day estimation window) was defined after seeing that, so it is a post hoc design and the report says so; A is left unchanged. The daily risk-free rate is DTB3/100/252, an approximation. Hyperparameters (learning rate, gradient budget, network size, cap) were fixed on synthetic data only; SAM's rho is limited to {0.05, 0.2}.
